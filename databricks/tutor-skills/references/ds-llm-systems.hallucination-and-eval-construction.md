# Hallucination/grounding measurement and eval-set construction

## Hallucination/grounding measurement

**Hallucination is not one failure mode.** Ji et al., "Survey of
Hallucination in Natural Language Generation," ACM Computing Surveys 2023
— https://arxiv.org/abs/2202.03629 — draws the taxonomy:

- **Intrinsic hallucination** — the output directly contradicts the
  source/context it was given. Detectable by comparison against that
  source: entailment/contradiction checking against the retrieved
  context or provided reference.
- **Extrinsic hallucination** — the output makes a claim that is neither
  supported nor contradicted by the given source — it's unverifiable from
  what was provided, or outright fabricated. This can't be caught by
  comparison against the source alone, since the source is silent on it;
  it needs an external fact-check (a knowledge base, a search, a human) or
  a stated policy that unverifiable claims are themselves a failure
  regardless of truth.

Applying one detection method to both is a category error: an entailment
checker against the retrieved context will correctly find zero intrinsic
contradictions on a purely extrinsic-fabrication output and wrongly signal
"no hallucination detected."

**Fine-grained factual measurement**: Min et al., "FActScore," EMNLP 2023
— https://arxiv.org/abs/2305.14251. Decomposes a long-form generation into
atomic factual claims and scores each against a knowledge source
independently, rather than judging the passage as a single unit — this
catches partial hallucination (a mostly-correct paragraph with one
fabricated detail) that a whole-passage judgment would average away.

**FActScore's own caveat**: the atomic-fact decomposition step is itself a
parsing/annotation choice — what counts as one "atomic fact" versus two,
and where a claim's boundary falls, is a modeling decision with its own
error rate. Report the decomposition method used, not just the resulting
score, and do not treat the decomposition as ground truth simply because
it's a preprocessing step rather than the headline metric.

**Where the check runs in a pipeline**: a cheap, deterministic or classic
check (entailment model, regex/rule-based fact extraction) gating an
expensive LLM's output before it ships is `ds-method-composition`'s
model-as-verifier / guardrail-cascade pattern — this subfield supplies the
intrinsic/extrinsic taxonomy and detection method the cascade's check
implements; it does not own the cascade's escalation-rule/calibration
gate.

## Generative eval-set construction

**Self-generated instruction data**: Wang et al., "Self-Instruct," ACL
2023 — https://arxiv.org/abs/2212.10560. Bootstraps a large instruction-
following eval/training set by having a model generate new instructions
and responses from a small human-written seed set. The structural risk:
the eval set is generated by the same *kind* of process being evaluated —
if the generator model has a systematic blind spot (a topic it always
gets wrong, a format it never produces), the self-generated eval set is
less likely to probe that blind spot in the first place, because the same
weakness that causes the failure also shapes what gets generated as a
"test."

**Adversarial, human-in-the-loop construction**: Kiela et al., "Dynabench:
Rethinking Benchmarking in NLP," NAACL 2021 —
https://arxiv.org/abs/2104.14337. Humans (or a human+model loop)
adversarially construct examples specifically to break the current best
model, in rounds. This directly counters benchmark saturation (a static
eval set stops discriminating once every model tops out on it) but
introduces its own complication: the target distribution shifts every
round, since round N's examples are adversarial against round-(N-1)
models specifically — a score from round 3 and a score from round 5 are
not measuring the same thing, and a longitudinal "model X improved from
round 3 to round 5" claim needs to control for that shift, not treat the
benchmark as fixed.

**Common wrong pattern**: standing up a Self-Instruct-style eval set using
the same model (or a close relative) that will later be evaluated against
it, with no check for whether the builder and the target share a blind
spot — and, separately, treating a Dynabench-style adversarial set's score
history as a stable time series without accounting for its round-over-
round distribution shift.

Once eval-set items exist, labeling them (redundant annotation, agreement
measurement, active-learning prioritization if the budget is constrained)
is `ds-labeling`'s — this subfield owns the generative-construction method
that produces the raw item set, not what happens to it afterward.
